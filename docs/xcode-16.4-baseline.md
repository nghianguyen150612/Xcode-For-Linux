# Xcode 16.4 Baseline Inventory (`x86_64`)

## Target

- **Target App:** Xcode 16.4 (`/Applications/Xcode_16.4.app`)
- **Xcode Build:** `16F6`
- **Host:** GitHub Actions `macos-15-intel`, verified `x86_64`
- **Validated Run:** [#6 / run 36074965821](https://github.com/nghianguyen150612/Xcode-For-Linux/actions/runs/36074965821)
- **Artifact:** `xcode-16.4-baseline-inventory`
- **Artifact SHA-256:** `11e2bb27c00950fb3891f158f9a01f21dac0260c0d44d1119852e1338c927e2d`

Xcode 16.4 is the bootstrap target because it is a modern Xcode release whose host executable still contains an `x86_64` slice, allowing the first Linux compatibility work to stay on native x86_64 rather than introducing CPU emulation.

## Method

The baseline is generated by `.github/workflows/xcode-baseline.yml` using `scripts/inspect-xcode.sh`.

The workflow:

1. verifies an Intel `x86_64` macOS runner;
2. resolves exactly Xcode 16.4;
3. inspects the main Xcode executable with `file`, `lipo`, `otool`, `nm`, and `codesign`;
4. inventories Mach-O files, architectures, executable Mach-O files, frameworks, dylibs, and XPC/helper bundles;
5. probes the Xcode CLI toolchain with `xcodebuild`, `xcrun`, Apple Clang, and Swift;
6. uploads metadata only. No Apple executable, framework, SDK, or runtime payload is copied into the artifact.

## Limitations

- This baseline proves the Xcode 16.4 host binary and much of its bundled tooling contain usable x86_64 code on macOS. It does **not** prove those binaries run under Darling or Linux.
- Counts describe the Xcode 16.4 bundle as installed on the validated GitHub-hosted runner; future runner image revisions may change auxiliary contents while the Xcode version remains the same.
- Framework-path counts are bundle-path inventory counts, not a claim that all entries are independent public APIs.
- Task 001 performs static inventory and native-macOS CLI probes only. No private API behavior or XPC protocol has been reverse engineered yet.

## Next Step
